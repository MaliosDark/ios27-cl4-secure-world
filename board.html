The road so far

The frontier - the current wall and beyond

Current wall · userspace

A writable /private/var

Full userspace boots and SpringBoard runs, but the rootfs is a read-only ramdisk with no data volume. SpringBoard aborts in BaseBoardUI with no writable temp dir. The fix is a kernel patch to mount md0 read-write at boot. This is the current frontier, ahead of the display work below.

Panel on ✓ · graphical UI missing

Real guest surfaces (IOMFB)

The panel ALREADY lights up and shows the real iOS boot log (full scanout). For the graphical UI, the guest still needs to deliver surfaces via IOMFB/EPIC - and run the full OS, not the ramdisk. It is the last stretch.

Secure path (CL4)

Handoff SPTM→SK + route the svc to the monitor

CL4 executes but its domain-setup needs the correct handoff and its svc calls to reach SPTM. And even booting fully, it needs ExclaveOS (164 MB) to register the display service.

Status as of this session · repo ios27-cl4-secure-world · full userspace boots and SpringBoard runs; the current wall is the read-only rootfs, with a kernel read-write patch in flight.
It is not firmware or keys - just the map of the device. The panel and console are lit; the last wall to a running shell is a writable filesystem, not the display.
